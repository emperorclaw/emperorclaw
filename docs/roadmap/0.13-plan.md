# 0.13–0.15 plan: close the high-impact gaps, then make the product shape itself

Written 2026-10-27 after refreshing the Paperclip comparison against EmperorClaw 0.12.5.

Three things are already in progress:
- failure messages with a one-click fix (roadmap 11.6);
- a folder choice for agents' knowledge notes;
- a light-mode audit.

This plan covers what comes next, in order.

## Quick path

| Release | Ships | Why first |
|---|---|---|
| 0.13 | Failure fixes, knowledge folders, light-mode fixes, inbox read/archive + undo, polish pass (shared empty states and skeletons, Pause/Resume all, sample client) | Small, visible, and it closes the "feels less finished" gap |
| 0.14 | Activity/audit, costs by client/project/model, global search | Agencies need all three: who changed what, what each client costs, and finding past work |
| 0.15 | Modules (on/off per company) + company templates, Hermes cron visibility | Lets each company look like what it is, and shows the jobs that are invisible today |
| 0.16+ | Server-side routines, structured collections (CRM-like), plugins later | The largest pieces; each one builds on the release before it |

## 0.14 details

| Item | What ships | Key decisions |

## 0.15: modules and templates

**Modules are switched on and off per company** (Settings → Modules): Customers, Automations, Timeline, Costs, Approvals, Knowledge collections, Display screens.

- A module that is off hides its nav entries and pages.
- Its MCP tools are left out of the agents' tool list and prompt, so there is less noise and fewer tokens.
- Its data is kept. Switching the module back on restores everything.
- The server guard is one helper: `moduleEnabled(companyId, key)`, used by routes, tools and nav.

**Company templates** set the starting modules. Choosing a template changes nothing else.

| Template | Modules on |
|---|---|
| Agency | All modules, Customers included |
| Product / solo | Customers off |
| Operations | Approvals and Automations on |

## 0.16+: collections, then plugins

- **Structured collections on the Brain** (CRM-like): typed fields, table and pipeline views, and generic MCP tools (`list_records`, `upsert_record`). A company builds its own Contacts, Deals or Vendors without us shipping a CRM.
- **Plugins** only after modules and collections are stable. A plugin is a package that declares collections, views and tools plus the permissions it needs. No arbitrary server code until there is a sandbox.

## Not planned

- Per-task privacy: customer scoping covers it.
- A Skills studio.
- A connectors catalog.
- Goals hierarchy and Cases.
